# Technical Design

## Change boundary

The behavior gap is that Supplement success currently means the response passed the Fact pipeline, not that deterministic review obligations were accounted for; runtime diagnostics expose only the latest execution; and World persistence can run after a no-op candidate. The relevant seams are the existing Supplement protocol/analyzer, the existing World analysis retry wrapper, the runtime diagnostic state, and the World save decision immediately before the frozen Floor coordinator.

Expected implementation files are limited to the existing `ai/` Supplement protocol/prompt/analyzer, `runtime/` World analysis/diagnostics/events, the existing UI application-state adoption seam if it can be proven safe, and focused tests. The Floor Coordinator remains read-only for this task.

Coverage and Identity Review sections are parsed independently from `[Fact]` blocks. IDs and review subjects are transient accounting objects. Facts remain normal parser → resolver → Evidence Guard inputs. Completeness is a separate terminal outcome and is required before a Supplement attempt can succeed.

Target IDs are generated after deterministic target ordering, using the current builder input and a versioned ordering contract. Required Identity Review subjects are species-level and derived only from existing/evidence subjects that the current architecture can safely enumerate; no biological-type vocabulary is generated by the host.

The existing retry wrapper is reused. A completeness failure supplies structured missing/invalid IDs to the existing retry prompt while retaining the complete Existing, permitted evidence, and deterministic review queues. Retry exhaustion is a failed analysis result with no canonical persistence.

Recent summaries are transient runtime diagnostics. They supplement, rather than replace, the latest summary and event-buffer history. The collector remains sampled-at-export-time and read-only.

Persistence is gated at the current World save decision. First compare the candidate canonical result with the authoritative current World; no-op results emit a skip diagnostic and never enter `saveWorldModel`. If a safe existing UI application-state adoption acknowledgement exists, use a transient candidate revision/fingerprint handshake before invoking the existing save path. UI never writes Floor. If no safe hook exists, do not invent a second writer or ambiguous acknowledgement path; defer only that gate and report it.

# 怀孕状态多页面 UI 原型设计

## Goal

设计总览、人物页和推演页的怀孕状态展示，并制作与现有 UI 尺寸一致的 HTML 原型。

## User value

- 用户可以在不打开 Debug 的情况下，快速判断某个人物是“疑似 / 观察”“已确认”还是没有妊娠结论。
- 总览页保持生产 UI 原有内容，不新增妊娠摘要；人物页提供单人物的权威状态，推演页说明受孕前观察路线是否仍在进行或已经被确认结果终止。
- 视觉展示必须和当前 BioWeave 面板、卡片密度、颜色语义及三端断点保持一致，不能另起一套 UI。

## Confirmed repository facts

- UI shell 使用 `960px` 面板、`50px` header、`42px` routebar，内容区在 `1200px / 768px` 两个断点切换。
- 总览页当前有统计条、人物总览、最近事件、当前推演、家系/世界概览和分析状态卡；事件标签已经支持“妊娠疑似 / 妊娠确认”。
- 人物页使用 `220px minmax(0, 1fr)` 的人物列表 + 详情工作区；详情中的“当前状态”保留生殖暴露、受孕事实和妊娠状态三个格。受孕事实显示是否已确认，妊娠状态在已确认时显示孕周（如“孕 8 周”）；疑似或未知时只显示观察/暂无结论，不伪造孕周。
- 推演页使用 `250px minmax(0, 1fr)` 的人物列表 + 时间线详情工作区，已有候选支线、已选支线、已触发和观察周期结束区块。
- 数据层已经区分 `pregnancy.current_status` 的 `suspected / confirmed`，但当前人物页的妊娠状态摘要没有直接渲染这两个状态；此次先做视觉原型，不改生产数据流。
- 当前怀孕确认与知情名单任务的既有设计明确：第一版知情名单只进入 Debug / 上下文，不自动新增普通 UI 编辑器；本原型可以评估是否需要一个只读的认知边界入口。

## Requirements

- 原型只读，不触发 API、不写入 Floor、不模拟业务保存；所有示例数据都在原型内部明确标注为演示数据。
- 在同一个现有 BioWeave shell 中展示三个页面：总览、人物、推演；页面切换使用现有 routebar 视觉，不创建新的顶层导航。
- 只做一个增量展示方案：在现有统计条、人物详情工作区和推演时间线中加入妊娠状态与知情边界，不制作 A/B/C 三套布局或方案切换器。
- 复用 UI 框架中的颜色语义：`good` 表示已确认、`warn` 表示疑似 / 观察、`muted` 表示未知或没有结论；不能用新的颜色体系制造第三种状态。
- 原型需覆盖 Desktop、Tablet 和 Mobile 尺寸，保持现有最大宽度、卡片间距、按钮高度、字体和无横向滚动约束。
- 原型应能通过项目预览或仓库根目录静态服务在浏览器中打开；所有新增控件都必须标注为原型演示，不属于生产 UI。

## Product decisions

- 普通 UI 需要展示“谁知道已确认怀孕”，但必须按妊娠人物分组，不能做成全局扁平名单。
- 人物页不在详情头部重复显示妊娠状态；当前状态区保留“生殖暴露”“受孕事实”和“妊娠状态”三个格。受孕事实格使用普通文字显示是否确认，不使用状态徽标或外框；已确认人物在该格右上角显示带生产按钮边框、适配卡片标题尺寸的“知情名单”按钮，点击后以编辑昵称同样的轻量只读弹层显示该人物独立的知情名单和“其他人物默认不知道”。妊娠状态格显示孕周，未确认状态显示观察中/暂无结论且不得显示周数，不增加第二个入口。总览页不显示妊娠摘要；推演页只复用现有详情 meta 的第一个状态徽标作为入口，不新增妊娠栏目。
- UI 不允许把“在场、怀疑、传闻或准备告知”显示成已知情；原型文案明确“其他人物默认不知道”。

## Acceptance Criteria

- [ ] 规划文档明确总览、人物、推演三页各自承担的状态展示职责。
- [ ] HTML 原型只包含一个增量展示方案，并始终复用现有 shell 的结构、尺寸和列表/详情层级。
- [ ] 原型使用现有 UI token、组件层级和 `1200px / 768px` 响应式断点，不另起独立视觉体系。
- [ ] Desktop / Tablet / Mobile 下无页面级横向滚动，人物页和推演页仍保持现有的列表 + 详情密度。
- [ ] 原型数据不写入生产存储，不调用 API，不改变现有页面或状态归约逻辑。
- [ ] 用户确认最终方案后，再单独进入生产 UI 实施任务；本任务的原型不会直接替代生产页面。

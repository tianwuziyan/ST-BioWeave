# 关联正文生理反应与推演卡片

## Goal

让用户能在人物推演页直接看出：当前推演中的哪一种潜在生理反应，已经在有效正文中真实出现；同时避免把这种对应关系误解为已经确认怀孕。

## Confirmed Facts

- 最新附件中，柳如烟的正文被解析为一条已确认的 `physical_symptom` Event，结构化症状类型为 `nausea`。
- 同一人物当前处于第 21–27 天推演阶段，当前卡片包括“恶心”“闻到气味不舒服”“情绪变化”“食欲变化”。
- 当前结构化 Event 只明确识别了 `nausea`；气味刺激和食欲不振存在于描述文本中，但没有分别成为独立结构化症状。
- 当前内置推演规则没有填写事实兑现条件，Runtime 也会跳过内置阶段卡片的事实状态演进，因此 Event 与推演卡片目前没有正式关联。
- 推演页已经支持卡片状态样式，但当前不会显示“已触发”的来源标注。

## Requirements

- 关联必须按人物进行，不得把甲人物的实际反应标到乙人物的推演卡片上。
- 第一版只允许结构化、确定性的匹配，不使用自由文本关键词进行猜测。
- `nausea` 应与当前人物的“恶心”推演卡片建立对应关系。
- 只匹配该人物当前观察轮次内、并且发生在对应推演时间段内的 Event；观察轮次开始前或其他时间段的同类症状不得命中当前卡片。
- 匹配仅表示“该表现已触发”，不得表示或暗示已经怀孕、已经确认受孕原因，或必须继续兑现某条剧情。
- 推演卡片仍属于当前阶段的可选参考；出现标注不能删除卡片，也不能使其他备选卡片消失。
- 对应关系必须来自当前 Chat 中仍然有效的 Floor/Swipe Event。正文删除、Event 删除、Swipe 切换或 Floor Version 失效后，不得继续显示标注。
- 产品 UI 不展示内部 Event ID、Projection ID 或原始 provenance；这些信息只进入 Debug。
- 在匹配卡片右上角显示醒目的“已触发”标注，并沿用现有 UI 框架与三端样式。
- 删除按钮以及“始终可能 / 当前可能出现”等现有功能和文案保持不变。

## Acceptance Criteria

- [ ] 柳如烟存在有效 `nausea` Event 且当前阶段有“恶心”卡片时，该卡片右上角显示“已触发”。
- [ ] 同一 Event 不会给其他人物的“恶心”卡片加标注。
- [ ] “闻到气味不舒服”和“食欲变化”不会仅因 Event 描述包含相似文字而被误标。
- [ ] 观察轮次开始前的恶心、其他推演时间段内的恶心，以及 Story Time 无法比较的症状均不会误标当前“恶心”卡片。
- [ ] 标注不会显示为“已怀孕”“已确认怀孕”或其他因果确认措辞。
- [ ] Event 来源楼层删除、Swipe 失效或 Event 被删除后，重新读取 UI 时标注消失。
- [ ] 当前阶段替换、回退旧楼层后，标注只由目标楼层之前最近的合法事实决定。
- [ ] 标注不改变推演卡片的保存、推送、删除、阶段替换与 API 上下文行为。
- [ ] Debug 能说明每张卡片是否命中、命中了哪条有效 Event，以及未命中的原因。
- [ ] 桌面、平板和移动端布局中，右上角标注不遮挡标题、正文、状态文案或删除按钮。

## Out of Scope

- 不根据症状判断或确认怀孕。
- 不修改 ST 正文内容，也不主动要求 ST 兑现推演路线。
- 不通过关键词或大模型二次分析，把一条描述自动拆成多个反应。
- 不在本任务中扩展“气味不舒服”“食欲变化”等新的结构化症状识别能力。
- 不改变现有推演阶段、时间范围、候选名单或推送文案。

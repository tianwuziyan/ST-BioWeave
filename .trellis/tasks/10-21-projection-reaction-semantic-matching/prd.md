# 增强推演生理反应识别

## Goal

设计正文已发生生理反应与可能变化的推演标题及内容之间的可靠关联机制，使“已触发”不再只识别固定的“恶心”分支，并让已经触发的卡片在健康恢复清理来源 Event 或推演切换阶段后仍能作为本轮历史使用，同时避免把未发生、否定、猜测或他人反应误标为当前人物已触发。

## Background

- 当前版本只支持结构化 `physical_symptom` Event 的 `nausea` 与内置“恶心”分支精确匹配。
- 实际正文可能同时出现疲倦、气味敏感、食欲变化、情绪变化、孕吐等多种表现，但当前卡片不会全部标记。
- 推演路线的标题和内容可能由生成结果或用户编辑发生变化，识别不能永久依赖某一条固定中文标题。
- 第一版“已触发”只是当前有效事实 Event 与推演候选的只读关联；实测发现健康系统在自然恢复后会清理同一身体症状 Event，阶段替换也会让旧卡退出当前视图，因此只读标记无法保存“本轮此前确实出现过”的反应。
- 现有实例中，柳如烟的一条 Event 同时描述了“恶心、气味诱发不适、食欲不振、干呕”，但结构化 `symptom.kind` 只有 `nausea`，因此当前只能点亮“恶心”。问题不只是 Projection 端缺少映射，也包括 Event 端只能表达一个主反应。
- 当前产品没有 Projection 标题/正文编辑入口；所谓“推演事件更改”在现阶段主要指不同阶段、生成结果或未来展示文案变化。安全设计应让展示文案与稳定反应语义分离。

## Requirements

- 扩大可关联的生理反应种类，并保持同一人物、当前有效 Floor/Swipe、当前观察轮次和对应时间范围隔离。
- 优先使用结构化 Event 事实；不得直接从原始正文重新做无约束关键词搜索。
- 允许利用推演路线的标题和内容理解该路线描述的生理反应，使标题或内容改写后仍有机会关联。
- 一条事实 Event 可以在只读匹配时提取多个明确出现的反应概念；主 `symptom.kind` 仍保持健康事实主分类，不新增持久化反应标签。
- 每条受孕前观察 Projection 候选应能得到可验证的反应语义：内置候选优先使用稳定 branch key；没有可用 branch key 时，才允许从当前 DTO 的标题和内容做严格、只读归类，不写回 Projection。
- 采用严格模式：只关联正文明确已经发生的反应，不通过医学相关性、程度相近或常见伴随关系扩展命中。
- 允许对已通过 Event 事实资格校验的结构化 `symptom.description` 做有限、确定性的反应短语识别，以补出同一 Event 中明确写出的多个表现；不得读取原始正文或 `source_evidence.text`。
- 允许对当前推演卡片的标题和内容做有限、确定性的反应语义归类，但它只用于判断“卡片在描述什么”，不能作为“正文已经发生”的证据。无法唯一归类或同时描述多种反应的卡片失败关闭。
- 必须阻止否定、未发生、将来可能、猜测、比喻、他人反应、医疗干预和非健康内容触发标注。
- 同一正文 Event 可以在语义确实对应时关联多个不同候选，但不得仅因共享泛化词语而批量命中。
- 当当前阶段的合格 Event 首次命中推演卡时，在该 Projection 卡片下保存有来源的“已触发”记录；业务隔离只按人物，记录依附现有 `projection_id`，不新增 `pregnancy_id`、独立周期编号或第二份身体事实。
- 健康系统继续正常识别、恢复和清理身体问题；健康自然恢复清理 Event 时，不撤销已经保存的推演触发记录。
- 阶段切换后，未触发的旧卡不再保留；已触发的旧卡进入当前人物的“本轮曾经触发”历史，不再作为当前可能反应显示。
- “本轮曾经触发”继续发送给 ST，但必须明确写成“此前出现过，不代表当前仍持续”；当前阶段候选继续按“当前可能出现”发送。
- 用户手动编辑或删除 Event 时，只根据修改后的当前阶段有效记录重算当前阶段标记；不倒改已经退出当前阶段的历史触发记录。
- 当前人物的观察过程结束或不再适用时，该人物的触发历史从当前作用范围清理，不再进入 UI 与 ST Context；历史 Floor 仍按既有 Floor/Swipe 所有权用于回退追溯。
- Debug 应能解释命中了哪个反应类别、采用了哪种匹配路径以及为何拒绝，但普通 UI 不显示 Event ID、技术原因或正文原文。
- 不增加新的正文分析 API 调用；首版复用现有 `symptom.kind` 与结构化事实摘要 `symptom.description`，不在 UI 读取时重新调用 AI。

## Acceptance Criteria

- [ ] “恶心”之外的已支持生理反应，在同人物、同轮次、合法时间范围内可显示“已触发”。
- [ ] 推演标题或内容经过同义改写后，只要语义类别仍明确，仍能与对应结构化 Event 关联。
- [ ] “没有恶心”“可能会疲倦”“担心她会吐”“另一个人物情绪波动”等内容不会误标当前人物卡片。
- [ ] 一个明确的结构化反应不会因为推演内容含“身体不适”等泛词而命中多个无关卡片。
- [ ] 健康自然恢复清理来源 Event 后，当前阶段已经保存的“已触发”不会消失，健康页仍正常结束该身体问题。
- [ ] 用户手动编辑或删除 Event 后，只按修改后的事实重算当前阶段标记；旧阶段触发历史不被倒改。
- [ ] 阶段切换后，当前 UI 只显示新阶段候选，旧阶段已触发项目进入“本轮曾经触发”，未触发旧卡不进入历史。
- [ ] ST Context 同时区分“此前出现过，不代表当前仍持续”和“当前阶段可能出现”，不得把历史触发当作仍在持续的健康状态。
- [ ] 当前观察过程结束后，不再显示或推送本轮触发历史；回退旧楼时只恢复该楼当时已经存在的记录。
- [ ] 触发记录不确认怀孕、不改变 Event、不影响健康恢复，也不新增 `pregnancy_id` 或重复保存周期身份。
- [ ] 普通产品 DTO/UI 只暴露安全的命中结果；Debug 提供有界、无正文泄漏的关联诊断。
- [ ] Core、Runtime、UI 和 Floor/Swipe 回归测试覆盖明确命中、改写命中、多人隔离、否定/猜测拒绝、泛词拒绝和失效撤销。
- [ ] 对已提供的柳如烟实例，严格模式命中“恶心、闻到气味不舒服、食欲变化”，不命中“可能出现孕吐”和“恶心加重”。
- [ ] 明确“呕吐/吐出内容物”才命中孕吐；“干呕但未吐”不命中。明确“比之前加重/持续恶化”才命中恶心加重；单次剧烈恶心不命中。

## Out of Scope

- 根据“已触发”自动确认怀孕或推进妊娠生命周期。
- 在 UI 中直接扫描原始聊天正文并自行判断生理反应。
- 为每次页面读取新增独立 AI 请求。
- 改变健康系统的识别、恢复、Event 清理规则或普通疾病判断。
- 把历史已触发反应解释为当前仍在持续，或据此确认怀孕。

## Technical Notes

- 当前没有 Projection 标题/正文编辑 API；本任务不新增编辑器。标题/内容变化仅作为 read-model 语义归类输入。
- 首版采用有界中文反应词表和明确排除条件，不增加新的 AI 调用、embedding、模糊相似度或 UI 关键词扫描。
- 首版只服务受孕前观察 `pre_confirmation` 推演；其他健康或通用 Projection 不自动套用该词表。
- 触发记录直接引用现有 Projection 卡片身份；读取与展示只按人物隔离。底层卡片已有的技术归属继续用于验证，但不为该标记新增或复制 `pregnancy_id`、`cycle_id` 等身份字段。

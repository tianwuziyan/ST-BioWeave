## 一、用户最终确认的业务规则

### 1. 推演按人物区分

- 推演页面先按人物展示，再看这个人物当前处于哪个阶段。
- 不同人物的阶段、已触发内容和当前候选可以不同，不能因为一个人物完成或切换阶段就删除其他人物的数据。
- 预确认阶段不使用 `pregnancy_id` 或独立周期编号隔离；当前推演触发记录按人物隔离即可。
- `pregnancy_id: null` 不是当前推演阶段的必要身份条件，因为此时还没有确认怀孕，也不应凭推演结果生成妊娠 ID。

### 2. 阶段和日期

- 观察阶段的业务范围为 14–42 天：
  - 14–20 天：疲倦/嗜睡、乳房敏感、气味或食物轻微变化、暂时无明显反应。
  - 21–27 天：恶心、闻到气味不舒服、情绪变化、食欲变化。
  - 28–42 天：恶心加重、可能孕吐、持续疲倦、始终没有明显反应。
- Floor 保存阶段编号，例如 `1-1`、`1-2`、`1-3`，不要保存容易失真的 `elapsed_story_days` 作为事实依据。
- UI 需要根据当前正文的 Story Time 实时计算并显示“第几天”。
- 阶段判断优先使用当前有效正文日期；最近 Floor 的快照只用于读取已有阶段和已触发内容。
- “没有明显反应”属于始终可能，不算已触发事实；其他路线属于当前阶段可能出现的候选。

### 3. 阶段切换时的保存规则

当前楼层必须保存当前人物截至当前阶段的完整已触发快照，但只代入已经触发的卡片：

```text
20楼：[A]
26楼进入下一阶段并新增 B：[A, B]
30楼更新 B：[A, B']
```

- 旧 Floor 不回写、不删除，保留用于回退追溯。
- 新阶段当前 Floor 直接保存完整快照，不再靠扫描多个历史楼层、按人物 ID 拼接。
- 阶段切换后，旧阶段未触发的候选不能进入当前历史。
- 旧阶段已触发内容在当前 UI 中属于“本轮曾经触发”，不是当前仍在持续；当前候选只显示新阶段的内容。
- 某人物观察结束时，当前 Floor 写入明确的空/终止快照，防止回退读取时复活旧数据；历史 Floor 保持不变。
- 多人物更新必须逐人物处理，A 的更新不能删除 B 的快照。

### 4. 健康模块和推演模块分开

- 健康系统可以正常识别、恢复并删除健康 Event。
- 健康 Event 被恢复清理后，不应删除本轮已经保存的推演“已触发”记录。
- 推演触发记录不是健康事实，也不能确认怀孕、改变健康恢复逻辑或生成妊娠生命周期事实。
- 健康恢复指导首次分析可一次得到全部阶段内容；进入新阶段时应复制已有完整数据到当前 Floor，不重复调用 AI。

### 5. ST 注入和提示词边界

- 插件内部计算和发给 API 的内容是两个端口：插件内部按日期、阶段和有效字段运行，不受“API 分析次数”限制。
- ST 正文生成结束、或构画式 settle 判定完成后，插件再开始计算和写入，避免正文还没落盘就读取旧内容。
- 仅打开角色卡、没有生成新正文时，可以走只读刷新/计时判定，但不能无限等待。
- 当前约定的插件上下文边界是：

  ```text
  <bioweave>
  ...插件上下文...
  </bioweave>
  ```

- 用户曾手动修改提示词/展示文案，把“发展方向”改成“生理反应”。不要恢复旧文案，也不要改动用户手动修改过的提示词。
- 本轮提交没有修改 `ai/**` 或提示词模板。

## 二、本轮已经完成的代码方向

### 严格生理反应识别

- 优先使用结构化 Event 的 `symptom.kind` 和受限的 `symptom.description`。
- 推演卡片优先使用稳定 branch key；没有 branch key 时才对当前卡片标题/内容做严格、唯一的语义归类。
- 支持恶心、气味不适、食欲变化、疲倦、乳房敏感、情绪变化、孕吐、恶心加重、持续疲倦等概念。
- 严格拒绝否定、猜测、将来可能、他人反应、泛化身体不适、干呕未吐、单次剧烈恶心等误命中。
- 不读取原始聊天正文做无约束关键词扫描，不新增 AI 分析请求。
- 一条结构化 Event 可以明确对应多个反应概念，但不会把泛词批量匹配到无关卡片。

### 人物级触发快照

- 在现有 Floor-owned `projection_timeline` 中保存人物级 `triggered_snapshots`。
- 当前快照包含人物、状态、阶段编号、已触发 Projection 及来源 Event ID。
- 触发记录和当前有效 Event 都经过当前 Chat、active Swipe、六字段 Floor Version 和现有 Coordinator 约束。
- 当前 UI、ST Context 和 Debug 优先消费当前 Floor 的完整快照。
- Debug 增加了继承数量、新命中数量、最终数量、写入结果、权威读回结果和匹配原因。

### 健康恢复阶段快照

- 健康恢复的多阶段指导保留完整数据和原始来源 Floor。
- 阶段未变化时复用最近完整记录；阶段变化或当前 Event 被手动编辑/删除时，复制完整健康指导到当前 Floor。
- 不重复调用健康分析 AI。
- 健康状态的事实 Event 与健康指导快照仍然分开。
